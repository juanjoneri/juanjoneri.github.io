How pages on this site are made

Private repos hold the data and the logic. This repo holds the rules, the shared style, and encrypted output only. Every private page lives at /p/<private-repo-name>/.

flow

private repo (e.g. net-worth)                 juanjoneri.github.io (public)
─────────────────────────────                 ─────────────────────────────
data + build script
   │ build             → dist/**/*.html  (plaintext, never leaves the runner)
   │ encrypt (staticrypt, per-site password)
   │ force-push        ─────────────────▶  branch site/net-worth   (latest copy only)
   └ stamp             ─────────────────▶  master: sites.lock.json
                                              │ deploy workflow
                                              ▼  only slugs in registry.json
                                           /p/net-worth/…  (GitHub Pages)

Nothing encrypted is committed to master, so changing a password fully retires the old one.

rules

1Raw data, credentials and business logic stay in the private repo.
2Pages show aggregates: totals, trends, categories. No account numbers, card digits, addresses, emails or phone numbers. People by first name or nickname only.
3Every private page is encrypted. Nothing private is ever committed to this repo in plaintext.
4One password per site, stored in the password manager and as that repo's STATICRYPT_PASSWORD secret. 6+ random words.
5Site names and paths are public (they are in registry.json), so pick repo names and titles that reveal nothing on their own.

register a private repo

  1. Add { "slug": "<repo-name>", "repo": "juanjoneri/<repo-name>" } to registry.json here.
  2. Generate a password in the password manager → private repo → Settings → Secrets → Actions → STATICRYPT_PASSWORD.
  3. Make a deploy key on your machine: 
    ssh-keygen -t ed25519 -N "" -C "<repo-name> → hub" -f hub_key
    hub_key.pub → this repo → Settings → Deploy keys (allow write).
    hub_key → private repo secret HUB_DEPLOY_KEY. Then delete both files.
  4. In the private repo, add a build script and .github/workflows/site.yml: 
    name: site
on:
  push: { branches: [main] }
  workflow_dispatch:
  schedule: [{ cron: "17 9 * * 1" }]   # cadence
jobs:
  publish:
    uses: juanjoneri/juanjoneri.github.io/.github/workflows/publish.yml@master
    with:
      build: bash build.sh      # must write plain HTML into dist/
    secrets:
      STATICRYPT_PASSWORD: ${{ secrets.STATICRYPT_PASSWORD }}
      HUB_DEPLOY_KEY: ${{ secrets.HUB_DEPLOY_KEY }}
      BUILD_ENV: API_TOKEN=${{ secrets.API_TOKEN }}   # optional: secrets for the build step only
  5. Push. The site appears at /p/<repo-name>/ a minute or two later.

page contract

entrydist/index.html is required.
subpagesAny dist/**/*.html. dist/q3/index.html → /p/<repo>/q3/. Link with relative paths.
filesOnly .html. Inline CSS, JS, SVG charts and images (data URIs). Anything else would be published unencrypted, so the build fails.
sharedMay reference public /assets/style.css and /assets/favicon.svg.
titleThe repo name in title case, everywhere: airtable-debts → Airtable Debts (landing page, unlock screen, browser tab, page <title> and heading). Subpages: Airtable Debts · Details.
head<meta name="robots" content="noindex, nofollow">
unlockOne password per site. "Remember for 30 days" covers all subpages of that site.
sizeKeep each page under ~2 MB; it is decrypted in the browser.

style

Terminal-report look: one monospace font, small sizes, thin and dashed rules, colour only to mean something. Link /assets/style.css to get all of this.

operations

cadenceEach private repo's schedule cron. Manual: Actions → site → Run workflow. Cron is UTC: for local-time windows, schedule both DST hours and gate on TZ=America/Los_Angeles date +%H in a first job.
build secretsAPI tokens live in the private repo's secrets and are passed as BUILD_ENV lines; only the build step sees them. Use read-only tokens scoped to one base or resource.
new passwordReplace the repo secret, re-run its workflow, update the password manager. The old one stops working.
unregisterRemove from registry.json; delete branch site/<repo> and its deploy key.
failed publishCheck the private repo's Actions log (private). Deploy errors are in this repo's Actions log; they never contain page content.
